Historie Gitu – vizualizátor repozitářů

Graf commitů s větvemi, merge commity a značkami, časová osa, filtry, vyhledávání a statistiky. Data načtete z lokálního exportu (úplný Git DAG) nebo z veřejného repozitáře přes GitHub API (vždy neúplná data). Vše se zpracuje jen ve vašem prohlížeči.

Načtení dat

Přetáhněte sem soubor .json z export_git_json.py, textový výstup jednořádkového příkazu, nebo uloženou odpověď GitHub API.

Ukázka je smyšlený repozitář (4 autoři, větve, merge, octopus merge, přejmenování, binární soubor). Naposledy načtená data se pamatují v tomto prohlížeči (IndexedDB), token GitHubu nikdy.

Limit bez tokenu: 60 požadavků za hodinu z vaší IP adresy, s tokenem 5 000. Jedno načtení = 1 požadavek na informace o repozitáři + 1 za každou stránku (+ 2 za větve a značky).

Rozhraní GET /repos/{vlastník}/{repo}/commits?per_page=100 vrací commity dosažitelné z jedné větve, nejnovější první, stránkované hlavičkou Link. Rodiče za poslední načtenou stránkou zůstanou „mimo načtená data“ a ostatní větve chybí, dokud je nepřidáte. Seznam commitů neobsahuje změněné soubory – ty lze v detailu commitu dočíst po jednom (1 požadavek). Časy vrací GitHub v UTC, pásmo autora tedy není známé. Token se drží jen v proměnné této stránky, neukládá se a posílá se jen na api.github.com.

Doporučeno – skript v Pythonu (jen standardní knihovna, Python 3.7+, git v PATH; repozitář jen čte):

Stáhnout export_git_json.py 
python3 export_git_json.py -C /cesta/k/repozitari -o historie.json
  • Windows: py export_git_json.py -C C:\projekty\repo -o historie.json
  • --max 5000 jen nejnovější commity, --od 2024-01-01 jen od data, --rozsah main develop jen vybrané větve (výsledek pak není úplný DAG – stránka to pozná a ukáže).
  • --emaily hash nahradí e-maily krátkým otiskem (pro sdílení), --emaily zadne je vynechá; --bez-souboru vynechá statistiky souborů.
  • Skript volá git log --all --parents --numstat -z --diff-merges=first-parent --format=… s náhodnou značkou na začátku a konci každého commitu a poli oddělenými znakem NUL, takže žádný obsah zprávy nerozbije čtení. Větve a značky čte git for-each-ref (anotované značky rozbalí na commit), zjistí HEAD a mělký klon.

      
Rychlá varianta – jeden příkaz (bash, Git Bash, zsh; bez statistik souborů a bez těla zpráv):

      
git log --all --date-order --decorate=full --format='%H%x1f%P%x1f%an%x1f%ae%x1f%aI%x1f%D%x1f%s%x1e' > git_historie.txt

      
Oddělovače jsou řídicí znaky 0x1F a 0x1E, které se v předmětu commitu prakticky nevyskytují; předmět je poslední pole, takže by ho stejně nerozdělily.

      
Formát JSON „git-historie-json“ verze 1

{
  "format": "git-historie-json", "verze": 1, "zdroj": "lokalni-git",
  "repo": { "nazev": "projekt", "head": "<sha>", "head_ref": "refs/heads/main", "melky": false },
  "parametry": { "rozsah": ["--all"], "max_pocet": null, "od": null, "soubory": true,
                 "emaily": "plne", "numstat_merge": "first-parent" },
  "refs": [ { "nazev": "refs/heads/main", "typ": "vetev", "cil": "<sha>" },
            { "nazev": "refs/tags/v1.0", "typ": "znacka", "anotovana": true, "zprava": "…", "cil": "<sha commitu>" } ],
  "commity": [ {
    "sha": "<40 hex>", "rodice": ["<sha>", …],          // pořadí rodičů jako v Gitu (první = hlavní linie)
    "autor": "Jméno", "email": "…", "datum": "2024-05-01T10:00:00+02:00",
    "commiter": "…", "commiter_email": "…", "datum_commit": "…",
    "predmet": "první řádek zprávy", "telo": "zbytek zprávy",
    "soubory": [ ["cesta", přidáno, odebráno], ["nová", 1, 0, "stará cesta"], ["obr.png", null, null] ]
  } ]
}

        
Úplnost se nepřebírá ze souboru, ale počítá: když každý rodič každého commitu je v datech a klon není mělký, jde o úplný DAG.
          Přijímá se i pole commitů z GitHub API uložené z prohlížeče nebo curl.
